Definition and Acronyms
Acronym
Definition
AC 
Acceptance Criterion. A condition used to verify that a function behaves correctly. 
API 
Application Programming Interface. A method for systems or services to communicate with each other. 
AuditLog 
System log that stores traceability information such as actor, action, target data, before/after values, IP address, and timestamp. 
BCrypt 
Password hashing algorithm used to store user passwords securely. 
Bottleneck Warning 
Rule-based warning that indicates inbound workload may exceed warehouse storage capacity or labour capacity. 
BR 
Business Rule. A required business constraint that the system must enforce. 
BV 
Boundary Value or Business Validation. A validation rule for allowed data ranges, limits, or calculation constraints. 
DB 
Database. Persistent storage for StockLite entities and transactions. 
DTO 
Data Transfer Object. Request or response data structure exchanged between frontend and backend APIs. 
EF Core 
Entity Framework Core. ORM(Object-Relational Mapping) framework used by .NET backend to access the database. 
ESP32 
IoT microcontroller platform used for electronic scale integration. 
FCM 
Firebase Cloud Messaging. Push notification service used to send mobile or realtime alerts. 
FDS 
Functional Design Specification. This document defines screen flows, screen specifications, APIs, interactions, messages, business rules, and background jobs. 
FE 
Feature code from Vision & Scope, such as FE-01, FE-02, or FE-16. 
FDS-local 
Business rule or validation defined only in the FDS because it describes UI, screen behaviour, or implementation-level handling that does not map directly to SRS business rules. 
FT 
Feature code in SRS, such as FT-01 Real-Time Inventory Tracking or FT-16 Returns Management. 
Hangfire 
Background job scheduler used to run recurring or delayed backend jobs. 
IoT 
Internet of Things. Hardware integration layer used by StockLite, mainly ESP32 scale devices. 
IotDevice 
Registered IoT scale device in a warehouse. 
IotDeviceCommand 
Remote commands sent to an IoT scale, such as TARE, RESET, or CALIBRATE. 
IotWeightLog 
Stable weight evidence sent from an IoT scale and attached to receiving, packing, or return inspection. 
JWT 
JSON Web Token. Token used for authenticated API access. 
KPI 
Key Performance Indicator. Summary metric shown on dashboard or reports. 
MVP 
Minimum Viable Product. Initial project scope excluding advanced integrations such as marketplace sync, accounting, courier automation, or financial return handling. 
NAC 
Negative Acceptance Criterion. A condition used to verify that invalid or unauthorized operations are rejected safely. 
NFR 
Non-Functional Requirement. Requirements related to performance, security, reliability, usability, maintainability, auditability, compatibility, backup, or localization. 
Put-away 
Process of assigning received goods to a storage location. 
QR 
Quick Response code used to identify ProductVariant or Location during warehouse operations. 
RBAC 
Role-Based Access Control. Access model that controls screens and actions based on user roles and permissions. 
RTW 
Requirement Traceability Worksheet. Artifact used to trace features, scenarios, business rules, tests, and related requirements. 
SC 
Scenario code in SRS, such as SC-03 or SC-11. 
SKU 
Stock Keeping Unit. Unique stocked item identifier stored on ProductVariant. 
SLA 
Service Level Agreement or expected maximum runtime/response time for an operation or background job. 
SRS 
Software Requirements Specification. Requirement document used as source reference for FDS. 
TARE 
IoT scale command that resets current weight baseline to zero. 
TDS 
Technical Design Specification. Technical design document referenced by FDS for implementation details. 
UI 
User Interface. Visual and interactive layer used by users. 
UX 
User Experience. Overall usability and interaction quality of the system. 
WMS 
Warehouse Management System. Software system for managing warehouse inventory, operations, and traceability.

General Navigation Rules
Users are routed after login according to role: System Admin and Warehouse Manager go to Dashboard (SCR-02), while Warehouse Staff goes to Mobile Staff Home & Task Queue (SCR-18).
Unauthorized screens are hidden from navigation and direct URL access is blocked by backend permission checks.
Inventory-changing actions are only available inside controlled workflows such as Confirm Receiving, Confirm Dispatch, approved Stocktake Adjustment, approved Customer Return, or approved Return-to-Supplier.
QR scanning flows always validate context. A valid ProductVariant QR can still be rejected if it does not belong to the selected inbound, outbound, stocktake, or return document.
Final stock updates are visible through Inventory Monitoring (SCR-03), Inventory Transaction History (SCR-11), Dashboard (SCR-02), and Reports & Analytics (SCR-17).
